# Terrarium Days 仕様書

| 項目 | 内容 |
| --- | --- |
| 文書版 | v0.1 / 2026-09-22 |
| 対象 | 1〜2週間で作るiOS(iPhone/iPad)向けプロトタイプ |
| 正式名称 | Terrarium Days |
| 参照元 | プロジェクト直下の `GAME.md` |

## 1. 製品概要

プレイヤーは一匹のヒョウモントカゲモドキを世話する。餌やり、水の交換、テラリウム清掃を行い、空腹・水分・清潔度を良好に保つことで健康と成長を促す。実時間で7日間、正常に世話を続けると成体へ到達する。

本作は、放置進行・状態管理・保存／復元を体験できる最小の2D育成ゲームである。ネットワーク接続は不要とする。

## 2. 対象環境

| 項目 | 仕様 |
| --- | --- |
| プラットフォーム | iOS (iPhone, iPad) |
| 画面向き | 縦固定 |
| 表現 | 2D、暖色系のテラリウム。無料素材またはプレースホルダー素材を使用 |
| 入力 | タップのみ |
| ペット数 | 1匹 |
| 保存先 | `Application.persistentDataPath` 以下のJSONファイル |
| 通信 | なし。機内モードでも動作すること |

## 3. MVPの範囲

### 実装する

- テラリウム画面、ヤモリ1匹、3種の世話アクション
- 5つの状態値、時間経過、放置進行、成長段階
- 最大5個の装飾選択
- JSONのセーブ／ロード
- 成長時のモーダル表示
- 開発専用の時間加速・値編集・セーブ削除パネル
- EditModeテストとiOS開発ビルド

### 実装しない

複数飼育、繁殖、病気、死亡、通貨、ショップ、広告、課金、ログイン、クラウドセーブ、通知、SNS、ローカライズ、分析機能、オンライン要素は対象外とする。

## 4. プレイサイクル

```text
起動／復帰
  ↓
前回保存時刻からの放置進行を反映
  ↓
状態値を確認
  ↓
餌やり・水交換・清掃
  ↓
状態が良ければ成長し、装飾や成長段階を解放
  ↓
一時停止／終了時に保存
```

## 5. 状態値と成長

### 5.1 状態値

すべての状態値は `0〜100` の範囲に丸める。表示は整数値とするが、内部計算は `double` を用いる。

| ID | 表示名 | 初期値 | 100の意味 | 0の意味 |
| --- | --- | ---: | --- | --- |
| `hunger` | 空腹度 | 80 | 満腹 | 空腹 |
| `hydration` | 水分 | 80 | 十分な水分 | 脱水状態 |
| `cleanliness` | 清潔度 | 80 | 清潔な環境 | 汚れた環境 |
| `health` | 健康 | 100 | 健康 | 弱っている状態。死亡しない |
| `growth` | 成長度 | 0 | 成体到達 | 成長開始 |

### 5.2 成長段階

| 段階 | `growth` の範囲 | 演出 |
| --- | --- | --- |
| Baby | 0〜49.999 | 初期見た目 |
| Juvenile | 50〜99.999 | 成長モーダル、装飾2個を解放 |
| Adult | 100 | 完了モーダル、装飾2個を解放 |

成体到達後も世話と状態変化は継続するが、`growth` は100で固定する。

## 6. 世話アクション

各アクションはタップ時に即時反映し、反映後に保存する。同一アクションを連続実行しても値は100を超えない。

| アクション | 対象 | 基本効果 | UIフィードバック |
| --- | --- | ---: | --- |
| 餌やり | `hunger` | +30 | 「ごはんを食べた！」 |
| 水の交換 | `hydration` | +30 | 「新しいお水にした！」 |
| 掃除 | `cleanliness` | +40 | 「テラリウムがきれい！」 |
| 装飾選択 | `selectedDecorId` | 数値変化なし | 選択中の装飾を反映 |

効果値は将来的に調整可能な単一のチューニングデータに置く。UIクラス内へ直接記述しない。

## 7. 時間経過と放置進行

### 7.1 時刻の扱い

- 保存時刻は `DateTimeOffset.UtcNow` をISO 8601文字列で保存する。
- 起動時、復帰時、開発用の疑似経過時に `OfflineProgressCalculator` を呼ぶ。
- 1回の放置計算に使う実経過時間は最大12時間へ丸める。12時間を超えていても、12時間分のみ反映する。
- 端末の時刻が過去へ戻った場合は経過時間を0とする。

### 7.2 既定のチューニング値

以下はプロトタイプ用の初期値であり、最終バランスではない。

| 項目 | 値 |
| --- | ---: |
| 空腹度の自然減少 | 4 / 時間 |
| 水分の自然減少 | 4 / 時間 |
| 清潔度の自然減少 | 3 / 時間 |
| 健康低下 | いずれかの世話状態が20未満の間、5 / 時間 |
| 健康回復 | 全世話状態が40以上の間、2 / 時間 |
| 通常の成長 | 全世話状態が40以上の間、100 / 168 / 時間 |
| 成体到達目安 | 健康な状態を合計168時間（7日）維持 |

### 7.3 計算規則

1. 経過時間を最大12時間へ制限する。
2. 1分単位の固定ステップに分割し、各ステップで空腹度・水分・清潔度を減算して0〜100へ丸める。
3. 3状態がすべて40以上なら、健康を回復し成長度を加算する。
4. いずれかが20未満なら、健康を減算する。
5. 上記以外は健康・成長を変化させない。
6. 成長度の段階閾値をまたいだ場合、段階変化イベントを1回だけ返す。

固定ステップは、オフライン進行とリアルタイム進行で同じ結果を得るために使用する。最大12時間では720ステップとなり、プロトタイプとして十分に軽量である。

### 7.4 開発用時間操作

開発ビルドのみ、以下を提供する。リリース対象のUIからは隠す。

- 時間倍率：`1x`、`60x`、`600x`
- 任意時間の疑似経過（分／時間）
- 各状態値の直接設定
- セーブデータ削除
- 最後に適用した経過時間の表示

時間倍率はデバッグ中のリアルタイム進行と疑似経過にのみ適用する。通常プレイの放置時間へは適用しない。

## 8. 保存データ

### 8.1 JSON例

```json
{
  "schemaVersion": 1,
  "lastSavedAtUtc": "2026-09-22T12:00:00.0000000+00:00",
  "hunger": 80.0,
  "hydration": 80.0,
  "cleanliness": 80.0,
  "health": 100.0,
  "growth": 0.0,
  "growthStage": "Baby",
  "selectedDecorId": "rock_01",
  "unlockedDecorIds": ["rock_01"]
}
```

### 8.2 保存／復元規則

- 起動時に保存ファイルがなければ、初期状態を生成して直ちに保存する。
- 世話アクション後、アプリ一時停止時、アプリ終了時に保存する。
- 読み込み失敗・JSON破損時は、壊れた内容を上書きせず、初期状態で開始してログに原因を出す。
- `schemaVersion` を必須とし、将来のデータ移行に備える。
- 状態値の読み込み後にも必ず0〜100へ丸める。

## 9. 画面仕様

### 9.1 テラリウム画面

| 領域 | 内容 |
| --- | --- |
| 上部 | 成長段階名、成長ゲージ、デバッグボタン（開発時のみ） |
| 中央 | テラリウム背景、ヤモリ、選択中の装飾 |
| 状態欄 | 空腹度・水分・清潔度・健康をバーと数値で表示 |
| 下部 | 餌やり、水の交換、掃除、装飾の各ボタン |

状態バーの色は、40以上を緑、20〜39を黄、19以下を赤とする。色だけに依存せず数値も表示する。

### 9.2 世話フィードバック

世話アクション後、対象付近または画面下部に短いメッセージを約1.5秒表示する。失敗状態は設けず、値が100でもタップ自体は受け付ける。100の場合は「もう十分だよ」のメッセージを表示する。

### 9.3 装飾ドロワー

- テラリウム画面から開く。
- 最大5個の装飾を一覧表示する。
- 未解放の装飾は選べず、解放条件を表示する。
- 初期解放は `rock_01` のみとする。
- Juvenileで2個、Adultで2個を解放する。

### 9.4 成長モーダル

Juvenile到達時とAdult到達時に一度だけ表示する。段階名、簡単なお祝いメッセージ、解放された装飾を表示し、「続ける」ボタンで閉じる。

## 10. システム構成

| コンポーネント | 責務 |
| --- | --- |
| `PetState` | 世話状態、健康、成長、段階、装飾の保持 |
| `CareTuning` | 効果量・自然減少・閾値・成長速度の一元管理 |
| `CareService` | 3つの世話アクションの適用 |
| `OfflineProgressCalculator` | 経過時間に応じた決定的な状態更新 |
| `SaveService` | JSON保存・復元・初期状態生成 |
| `TimeService` | UTC時刻取得、休止／復帰通知、デバッグ時間倍率 |
| `TerrariumPresenter` | UI表示と入力をドメインロジックへ接続 |
| `DeveloperPanel` | 開発専用の時間・状態・保存操作 |

`OfflineProgressCalculator`、`CareService`、`SaveService`のデータ変換は、`MonoBehaviour`に依存しないC#コードとして実装する。

## 11. 受け入れ条件

### 機能

- 新規起動で5状態値が初期値で表示される。
- 3つの世話アクションが正しい対象値へ即時反映され、100を超えない。
- 端末復帰時に、最大12時間分の放置進行が1回だけ適用される。
- `600x` のデバッグ速度でAdultへ到達し、エラーなくモーダルが表示される。
- 装飾は解放済みのものだけ選択でき、再起動後も選択状態を維持する。
- 保存ファイルを削除すると初期状態から開始できる。

### テスト

- `StatusValue` の0〜100丸めをEditModeテストで確認する。
- 放置時間0、12時間超過、端末時刻逆行、各閾値40／20をEditModeテストで確認する。
- 保存→読込で全プロパティが維持されることをEditModeテストで確認する。
- CLIテスト実行後、JUnit XML結果が生成される。
- iOS開発ビルドが端末へインストールされ、テラリウム画面を表示できる。

## 12. 実装順序

1. `PetState`、`CareTuning`、値の丸め
2. `CareService` と3アクションのEditModeテスト
3. `OfflineProgressCalculator` と境界テスト
4. `SaveService` と保存往復テスト
5. テラリウム画面と状態バー
6. 世話ボタン、フィードバック、成長モーダル
7. 装飾ドロワーと解放
8. 開発パネル
9. iOS実機ビルドと調整

各工程は1つの受け入れ条件を満たす小さな変更として実施し、実装・テスト・見た目調整を同じ変更へ混在させない。
