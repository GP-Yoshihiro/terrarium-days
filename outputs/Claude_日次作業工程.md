# Claude Code 日次作業工程・運用方針

## 基本方針

Claude Codeには、1日に**完了条件が1つだけの小機能**を最大2本まで任せる。長い会話を継続せず、機能ごとに短い新規セッションへ切り替える。

```text
仕様を読む → 小機能を1つ実装 → 狭いテストを実行 → 結果を記録 → 次の小機能
```

実装、広範囲のリファクタリング、見た目調整、原因不明のデバッグを、同じ依頼へ混ぜない。

## 1日の目安（実作業6時間）

| 時間 | Claude Codeへの依頼 | 人が確認すること |
| --- | --- | --- |
| 15分 | `AGENTS.md`、`CLAUDE.md`、`GAME.md`、仕様書を読み、今日の対象を1つに絞る | 前日の未解決事項と今日の完了条件 |
| 90分 | 機能Aを実装する | 変更対象が予定ファイルだけか |
| 30分 | EditModeテストまたはコンパイル確認 | テスト結果・ログの有無 |
| 15分 | 差分を要約し、次の作業候補を1つ出す | 仕様から外れていないか |
| 90分 | 機能B、または機能Aの不足テストを実装する | 1日の上限を超えて機能を増やしていないか |
| 30分 | 狭いテストを再実行する | 結果XMLまたはログ |
| 30分 | `GAME.md`のチェックリストと作業メモを更新する | 明日の開始地点 |
| 残り | Unityエディタでの目視確認、実機確認、素材差し替え | Claude Codeへ渡す次の小さい課題を決める |

1日のClaude Code利用は、原則として合計2〜4セッションに分割する。エラー調査が長引く場合、推測を続けず、ログ・再現手順・期待動作だけを残して翌セッションへ切り替える。

## Claude Codeの駆動ルール

### 開始時

```text
AGENTS.md、CLAUDE.md、GAME.md、outputs/Terrarium_Days_仕様書.md を読んでください。
今日の対象は [機能名] のみです。
対象外のファイルは変更せず、実装前に変更予定ファイルと受け入れ条件を5行以内で示してください。
```

### 実装時

```text
/unity-feature

対象: [例: PetStateの初期値と0〜100への丸め]
変更可能: [対象ファイルの絶対または相対パス]
受け入れ条件:
- [観測可能な動作]
- [追加・更新するEditModeテスト]
対象外のリファクタリング、パッケージ追加、UI変更は行わないでください。
```

### 検証時

```text
/unity-verify

今回の変更に対する最小のEditModeテストだけを実行してください。
結果、実行コマンド、JUnit XMLまたはログのパスを簡潔に報告してください。
コードは変更しないでください。
```

### エラー時

```text
/unity-debug

再現コマンド: [コマンド]
期待結果: [期待動作]
実際の結果: [エラー]
ログ: [ログパス]
最小の原因候補を1つだけ調べ、修正案はまだ適用しないでください。
```

## 夜間の扱い

夜間は、プロジェクト内容を変更する自律作業を実施しない。実行する場合は、次のような読み取り中心の確認に限る。

- Unity CLIのEditModeテスト
- Android開発ビルド
- テスト結果XML・Unityログの収集
- `git status --short` による変更一覧の出力

テスト失敗時は自動修正を続けず、失敗ログと終了時刻だけを残して停止する。特に`Library/`、`Temp/`、`ProjectSettings/`を削除・再生成する対処は行わない。

## 8日間の大まかな実装順序

| 日 | 完了させる縦切り | 主な検証 |
| ---: | --- | --- |
| 1 | Unity CLIテストを安定実行し、`PetState`と値の丸めを作る | 0〜100丸めのEditModeテスト |
| 2 | 餌やり、水交換、掃除の`CareService`を作る | 各アクションの値変化テスト |
| 3 | `OfflineProgressCalculator`を作る | 0時間、12時間、時刻逆行、閾値テスト |
| 4 | JSON保存・復元を作る | 保存往復テスト、破損データ時の初期化 |
| 5 | テラリウム画面と状態バーを作る | エディタでの目視確認 |
| 6 | 世話ボタン、フィードバック、成長モーダルを作る | 3アクションの画面操作確認 |
| 7 | 装飾解放、装飾選択、開発パネルを作る | 600xでAdult到達を確認 |
| 8 | Android開発ビルド、実機確認、バグ修正 | APKのインストールと起動 |

## 1日の終了条件

次の4点を短く残して終える。

1. 変更したファイル一覧
2. 実装済みの受け入れ条件
3. 実行したテストと結果
4. 明日の作業を1つだけ

## トークン上限を避けるための禁止事項

- 「ゲーム全体を作って」「全部確認して」のような広い依頼をしない。
- 生成フォルダの`Library/`や`Temp/`を会話へ貼り付けない。
- エラーログは先頭から全量貼らず、最初のコンパイルエラーと関連箇所だけ渡す。
- 同じ会話で3回以上失敗したら、新しい会話に再現手順と最小ログだけを渡す。
- テスト成功の確認なしに次の機能へ進まない。
