## 体制（利用者の承認済み）
- スキル `hq-section-orchestration` と `lean-token-workflow` に従う。役割の定義は `~/.claude/agents/`（planner / programmer / transcriber / graphics / task-reviewer / log-triage）。
- 流れ：
  1. **設計セッション（Opus）**：仕様の未決事項だけを利用者に確認 → `planner` に計画を書かせる → 承認をもらう → セッションを終える。
  2. **実行セッション（新しく開く。統括は Sonnet でよい）**：`/autocompact 200000`。作業記録（`.superpowers/sdd/<plan>/progress.md`）と計画の見出しだけ読んで、タスクごとに作業者 → `task-reviewer`、最後に Opus の最終レビュー。
- ローカル LLM（`local-llm-offload`、qwen3-4b-2507）はログからのエラー抜き出しだけに使う。日本語の文章・翻訳には使わない。
- GPT/Codex 連携は保留（利用者判断：今日の作業次第で再検討）。

## 段階3で決める必要がありそうなこと（設計セッションで利用者に確認）
1. **相場（§10.1）を先に作るか**：ショップの販売価格は「相場×1.2」、卸売りは「相場の40%」で、どちらも §10.1 の基準値が要る。基準値の表と計算だけを段階3で作り、需要の上下（イベントごと）は段階6に残す案が自然。
2. **装飾をケージごとにする移行**：§9「成長による解放をやめて購入制にする。解放済みの装飾は所持品として残す」と §6.1「装飾はケージごと、小型1／標準2／大型3」。今は1匹ごとに `SelectedDecorId` と `UnlockedDecorIds` を持っている。
3. **生体の入れ替わり**：毎月4〜6匹。遺伝子型・性格の作り方（性格は購入後に判明＝`PersonalityKnown=false`、いつ判明にするか）。
4. **台帳の画面**の範囲（§6.2：個体一覧・家系図・お金の出入り・売上の履歴）。家系図と売上は後の段階でもよいか。

## 段階3に持ち越された指摘（前の段階の作業記録から）
- お金：`Wallet.Charge/Earn/TrySpend` が負の金額を拒まない。所持金ちょうどを使い切るテストがない。
- 画面：ケージに入らずにホームからタブへ行けるようにする（段階1の最終レビューの推奨）。`home-incubator-button` に処理がない。ホーム・一覧のサムネイルが小さい（256px の枠の大半が余白 → 体の範囲で切り出す）。`ColonyChanged/TabChanged` の購読を `OnDestroy` で外していない。
- 保存：壊れたセーブのバックアップのコピー自体が失敗したとき（容量不足）に上書きしてしまう（段階3に回した判断）。スキーマなしの JSON を旧形式とみなして移行してしまう。
- 表示：プロフィール欄が文字の途中で折り返す（「好奇心旺盛」「ヘテロ不明」が分かれる）。
- 段階4の前に：デバッグの早送りが保存のたびに戻る問題、色を変えたスプライトのキャッシュの上限。
