## spec の主な決定（計画の前提）

1. 毎月15日に開催。4・7・10・12月は大規模（出店料10,000円・最大10匹・行動8回）、ほかは小規模（3,000円・最大5匹・行動5回）。締め切りは前日（14日）。
2. 申し込みで出店料を払う（返らない）。前日までは出品を直せる。開催日0:00に基準値・確率・乱数の種を固定する。
3. 売れる確率はロジスティック（価格 ÷ 基準値、上限1.2／1.5、最大98%）。接客 N 回で全体の確率がちょうど P、ブースを見る行動は0.6倍。値引きの許容幅は0〜20%の5段階。
4. 当日は「接客する」「他のブースを見る」を N 回。結果は押した時点で種から決まり、遊んだ時刻に依存しない。演出は10〜15秒で、決まった結果を見せるだけ。
5. ブースでは1回1〜3匹の売り物。珍しい個体が出る確率は15%／25%で、ショップには出ない。空きケージがないと買えない。
6. 出品中の個体はペアリング・卸売りに使えない。売れた個体は `RemoveAnimal` で手放す（家系の記録に残る）。台帳の時刻は遊んだ時刻。
7. セーブはスキーマ4。スキーマ3は「申し込みなし」で読み、異常な値はその出品だけ取り消す。

## 計画で分かった、既存のコードと spec の食い違い

1. 上の `ColonySaveService.cs:80`（スキーマ3が移行の経路に入る）。
2. `ShopService.BuyAnimal` は `Cages.Find(c => c.IsEmpty)`（並び順の最初）で、番号の小さいケージとは限らない。イベントの買い物は `Colony.FirstEmptyCage()` を使う（ショップは変えない）。
3. `ConfirmDialog` は「はい」を押せなくできない（上の Task 13）。
4. `RemoveAnimal` がすでに家系の記録を残す。生きている個体は家系の記録を持たないので、出品の取り消しの名前は個体か `Lineage` から取る。
5. `EconomyTuning` に出店料の欄がない。出店料などの数字は `EventSchedule` の定数に置いた。
6. 既存のタブの金額は「¥28,500」、spec の例は「28,500円」。イベントタブだけ「円」にした（★16）。
7. `EventText`・`EventReplay` は既存の `*Text` と同じく UI の名前空間（`TerrariumDays.UI`）に置いた。
