# 段階6 相場・イベント 設計書

- 親の仕様書：`docs/superpowers/specs/2026-09-25-breeder-sim-design.md`（§10 相場と販売確率、§11 イベント、§12 セーブ、§13 テスト、§14 段階6）
- 設計の話し合い：2026-10-20。
- 完了の条件（§14 に買い物を加えたもの）：出品 → 当日（行動を使う）→ 売上の加算までを一通り遊べる。当日に他のブースで個体を買える。PlayMode のテストで「申し込み → 当日 → 接客と買い物 → 集計 → 台帳に売上」が1周通る。

## 0. 狙い（利用者の言葉から）

- 「やった」と感じるのは、**ショップに出ないモルフ・遺伝要素に出会えたとき**と、**高額の取引が成立したとき**。
- イベントは**売る場所であり、買う場所でもある**。ただし当日の行動の数に限りがあるので、両方を全部はできない。お金を集めに行くか、新しいモルフを探しに行くかは遊ぶ人が決める。
- 見た目の違いで珍しさを出す素材はない。珍しさは**モルフ名と遺伝要素**（組み合わせ・ヘテロ）で出す。

失敗とみなすこと（動いていても）：
- 売るのも買うのも同時に全部できてしまい、選ぶ意味がない。
- 珍しい個体がショップと同じものばかりで、出会いの驚きがない。
- アプリを閉じていたせいで、当日の行動（特に買い物）を遊べずに終わる。

## 1. 決定事項（利用者が決めたこと）

| # | 論点 | 決定 |
|---|---|---|
| 1 | イベントでできること | 販売と買い物の両方 |
| 2 | 当日の進め方 | 決まった回数の「行動」を使う。1回ごとに「他のブースを見る（買える個体が出る）」か「接客（出品した個体が売れやすくなる）」を選ぶ |
| 3 | 当日にアプリを開かなかったら | イベントは遊ぶ人を待つ。当日を過ぎてからでも、次にアプリを開いたときに「当日の行動」をすべて遊べる（ゲーム内の1日は実時間で約48分しかないため。2026-10-20に決定） |
| 4 | 「珍しい」の意味 | ショップに出ないモルフ・遺伝要素。見た目の違いではない |

## 2. 仕組み

### 2.1 開催の予定（§11 のとおり）
- 小規模「レプタイル・マルシェ」：毎月15日（4・7・10・12月を除く）。出店料3,000円、出品は最大5匹。
- 大規模「ジャパン・レプタイルズ・フェスタ（春・夏・秋・冬）」：4・7・10・12月の15日。出店料10,000円、出品は最大10匹。
- イベントの番号は、ゲーム開始からの月の通し番号とする（1か月に1回なので重ならない）。需要（`EventDemand.For`）の種にも使う。

### 2.2 準備（開催日の前日まで）
- イベントタブで、出品する個体・価格・値引きの許容幅を決め、出店料を払って申し込む（台帳の「出店料」）。
- 価格を動かすたびに、基準値（需要込み）・売れる確率・期待値をその場で表示する（§10.2）。
- 出品できない個体：抱卵中のメス、ペアリング中の個体、孵化トレイの個体、衰弱中の個体（★判断A）。
- 申し込んだ後でも、前日までは出品の内容を直せる。出店料は返らない（★判断B）。
- 出品中の個体は、イベントが終わるまでペアリング・卸売りに出せない。画面に「出品中」と出す（★判断C）。
- 申し込まずに当日を迎えたら、そのイベントには参加しない（何も起きない）。
- 申し込めるのは次のイベントだけ。受付は前のイベントが確定した直後から始まる。閉じていた間に過ぎた、申し込んでいないイベントは何も起こさない（★判断M）。
- 基準値・確率・期待値は前日まではその時点の個体の状態で計算し直す。開催日の0:00に出品の内容と基準値を固定する（成長段階や衰弱が変わっても当日の数字は動かない）。0:00の時点で出品できない状態になった個体は出品を取り消す（★判断N）。

### 2.3 当日の行動
- 行動の数：小規模5回、大規模8回（★判断D）。
- 「接客」：出品した個体の、この行動での売れる確率を1倍にする（下の 2.4）。
- 「他のブースを見る」：ブースを1つ訪ね、売り物を1〜3匹見せる。好きなだけ買える（お金が足りる範囲で）。訪ねたブースの売り物はその日のうちならいつでも買える（行動を使わない）（★判断O）。この行動のあいだも出品した個体は売れるが、確率は0.6倍（★判断E）。
- 1回の行動ごとに短い演出を流し（2.6）、その行動で売れた個体をログに出す。
- 行動は、開催日の0:00（ゲーム内時刻）から使える。日付が過ぎても、遊び終わるまで待つ（締め切りなし）。
- 「残りを全部接客にする」ボタンで、残りの行動をまとめて接客に使える（買い物をしない人のため）。

### 2.4 売れる計算（§10.2 を行動ごとに分ける）
- 個体ごとの「イベント全体で売れる確率」P は §10.2 の式のとおり（上限は小規模1.2・大規模1.5、k = ln3 ÷ 0.3、最大98%）。
- 行動の数を N とする。1回の「接客」で売れる確率は a = 1 − (1 − P)^(1/N)。こうすると、全部を接客に使ったときに全体の確率がちょうど P になる。
- 「他のブースを見る」行動のときは、a × 0.6 にする。
- 値引きの許容幅 d は 0・5・10・15・20% から選ぶ（★判断F）：
  - 比率 r の計算には、実効の価格「価格 × (1 − d/2)」を使う。
  - 売れたときの実際の金額は「価格 × (1 − d × u)」。u はその取引の乱数（0〜1）。100円単位に丸める。
  - 期待値は「価格 × (1 − d/2) × P」。
- 売れた個体はその場で手元からいなくなり、台帳の「イベント売上」に入る。家系の記録（段階5）にも「手放した」として残す。

### 2.5 他のブースの売り物（珍しさの出どころ）
- 売り物は、ショップの品ぞろえ（`ShopStockGenerator`）とは別の表から作る。表には「ショップに出ないもの」を入れる（★判断G）：
  - 遺伝要素が3つ以上の組み合わせ（例：トレンパー＋エクリプス＋マックスノー）
  - ベル・レインウォーターを含む組み合わせ
  - 確定ヘテロが3つ以上ある個体、多因子の値が高い個体
  - ショップにも出るモルフが混ざってもよい
- 1回のブースで「珍しい」個体が1匹以上出る確率：小規模25%、大規模45%（★判断H）。大規模は愛好家が多い設定なので高くする。
- 売り物の個体の中身はショップの個体と同じ形（成長段階・体重・分かっているヘテロを表示、ベビーは雌雄不明、性格は購入後に判明、衰弱なし）。成長段階はヤング・アダルトを多めにする（★判断P）。
- 値段は「相場 × そのイベントの需要 × 1.0〜1.15」（★判断I）。値切りはしない（固定の値段）。
- 買った個体は、空いているケージがあれば番号の小さい空きケージへ、なければ孵化トレイへ入る（★判断J）。孵化トレイに入っても「弱らない猶予」はない（孵化したベビーだけの決まり）。孵化トレイに定員はない（段階5の★12）。台帳は既存の「生体の購入」。
- 珍しい個体が出たときは、演出とログで目立たせる（例：「掘り出し物！」の表示）。

### 2.6 演出
- イベントタブを開くと、ブースの絵、来場者のドット絵、吹き出しの会話、下の固定枠のログ（例：「11:24 レイプター♀ 売約（28,500円）」）を出す。
- 1回の行動の演出は10〜15秒。全部の行動で1〜2分になる。演出は飛ばせる（★判断K）。
- 演出は確定済みの結果を見せるだけで、結果を変えない。
- 最後に集計を出す：売れた個体、売れ残り、総売上、買った個体と支払い、出店料、収支。
- 来場者のドット絵は新しく作る（人の形の簡単な絵、2〜3種、歩きの2コマ程度）。

### 2.7 確定と再現性
- 行動の結果は乱数の種から決める。種は（イベントの番号、出品の内容と価格、行動の番号、行動の種類）から作る。同じ選び方をすれば同じ結果になる。
- 当日の途中でアプリを閉じても、使った行動の結果は保存されている。続きは次に開いたときに遊べる。
- 行動を使い切ったら（または「残りを全部接客にする」を押したら）イベントを確定し、集計を出す。確定したら出品していた個体の「出品中」を外し、次のイベントの受付を始める。
- 遊び終わっていないイベントがあるあいだは、次のイベントに申し込めない。そのあいだに次のイベントの日が過ぎたら、そのイベントには参加しない（★判断Q）。
- 台帳に残す日時は、その行動を遊んだ時刻とする。説明の文にイベントの名前を入れる（★判断R）。

### 2.8 通知
- 段階5と同じ、アプリ内の通知（画面のお知らせ）を使う。OS の通知は使わない。
- 開催日の3日前・前日に「申し込みの締め切り」を知らせる（申し込んでいない場合だけ）（★判断L）。
- 開催日の0:00に「イベント当日です」を知らせる。
- 当日を過ぎてもまだ遊んでいないイベントがあれば、アプリを開いたときに「イベントの続きがあります」を知らせる。
- 文の細かい言い回しは実装に任せる。

### 2.9 セーブ
- スキーマを1つ上げ、次を保存する：申し込みの内容（イベントの番号、個体の番号・価格・許容幅、0:00に固定した基準値）、当日の進み（使った行動とその結果、訪ねたブースの売り物、買ったもの）、最後に確定したイベントの集計。
- 古いセーブには「申し込みなし」として移行する。異常な値（存在しない個体の番号など）はその出品を取り消して読み込む。
- 申し込みから当日までのあいだに出品した個体がいなくなったら（死んだなど）、その出品は取り消す。

## 3. 範囲外（今回しないこと）

- 来場者との値切りのやり取り（許容幅で代わりにする）。
- 見た目（色や模様の個体差）による珍しさ。
- イベントの規模や日付を遊ぶ人が選ぶこと。
- 相場の時期による変動（需要はイベントごとの乱数だけ）。

## 4. 実装に任せること

- 画面の配置（準備・当日・結果の切り替え方、ブースの絵の細部）。既存のタブとカードの見た目に合わせる。
- 来場者の会話の文、ブースの名前。
- 売り物の表の重みの細かい値（2.5 の方針の範囲で）。
- デバッグ用の操作（例：次のイベントの当日まで進める）。

## 5. テスト

- EditMode：
  - 開催の予定（どの月が大規模か、締め切り）
  - 売れる確率と 2.4 の分け方（全部接客で P に一致する）
  - 値引きの許容幅と期待値
  - 同じ種から同じ結果が出ること
  - 当日を過ぎてから遊んでも同じ結果になること、「残りを全部接客にする」、出品した個体がいなくなった場合の取り消し
  - ブースの売り物が「珍しい」の条件を満たす割合
  - セーブの移行と異常値
- PlayMode：申し込み → 当日 → 接客と買い物 → 集計 → 台帳に売上、の1周。演出は飛ばして確かめてよい。
- 画面キャプチャ：準備・当日・結果の3画面。
